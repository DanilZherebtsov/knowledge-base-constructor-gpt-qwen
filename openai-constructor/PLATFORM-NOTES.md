# Что проверено, что не проверено, чего нет

Редакция получена переносом с конструктора для Claude Code (16.09.2026). Перенос делался по документации вендора, **боем не проверялся ни разу**. Этот файл существует, чтобы неизвестное было названо, а не выглядело как знание: разбор предыдущей чужой адаптации показал, что ломается конструктор именно там, где адаптирующая модель уверенно предположила, чего у платформы нет.

Файл — для человека и для агента при переносе следующих правок. В собранный проект он **не идёт** (см. перечень лесов в `START-HERE.md`, шаг 5).

## 1. Проверено по документации вендора

| Что | Итог |
|---|---|
| Имя корневого файла | Codex ищет `AGENTS.override.md` → `AGENTS.md` → `TEAM_GUIDE.md` → `.agents.md`; имена вне списка игнорируются |
| Порядок склейки | глобальный `~/.codex/AGENTS.md` → корень репозитория → вложенные папки, от корня вниз |
| Хуки | `SessionStart`, `Stop`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PreCompact`/`PostCompact`, `SubagentStart`/`SubagentStop`, `SessionEnd`, `Interrupt`; конфиг — `.codex/hooks.json` или `.codex/config.toml` |
| Контракт хука | JSON на stdin; на выход `additionalContext`, `systemMessage`, `"continue": false`; код выхода `2` блокирует |
| Субагенты | TOML в `.codex/agents/`, обязательные поля `name`, `description`, `developer_instructions`; свой поток, наружу сводка |
| Бюджет инструкций | `project_doc_max_bytes`, по умолчанию 32 KiB, считает **всю склейку**; при превышении файлы перестают добавляться **молча** |
| Десктопное приложение ChatGPT | локальный проект подключает папку, ChatGPT читает и меняет в ней файлы; основная папка проекта используется для автоматического обнаружения `AGENTS.md`, скиллов и `config.toml` |

## 2. НЕ проверено — смотреть в первую очередь

1. **Бюджет инструкций — главный риск.** Собранный `AGENTS.md` весит около 31 KB при лимите по умолчанию 32 KiB, и лимит общий с глобальным файлом человека. Мы кладём `.codex/config.toml` с поднятым `project_doc_max_bytes`, но документация описывает этот ключ для `~/.codex/config.toml` — **действует ли он на уровне репозитория, неизвестно**. Что делать: после первой сборки спросить у агента, видит ли он раздел «Bootstrap» (это самый хвост файла). Не видит — человеку прописать `project_doc_max_bytes = 262144` в своём `~/.codex/config.toml`. Профилактика меряет размер на каждом прогоне (`lint.md`, «Размер корневого файла»).
2. **Исполняются ли хуки в десктопном приложении ChatGPT** наравне с Codex CLI. Известно, что на Codex Desktop были версии с регрессией, когда хуки из `.codex/hooks.json` переставали запускаться вовсе. Проза-правила в `AGENTS.md` написаны как **пол**: если хук не сработал, проверку делает агент сам. Проверить: запустить сессию и посмотреть, приходит ли записка о просроченной профилактике.
3. **Путь запуска хука.** В конфиге команда задана относительным путём (`python3 .codex/hooks/freshness_check.py`), а сам скрипт ищет корень проекта, поднимаясь от `cwd` до папки с `AGENTS.md`. От переменной окружения не зависим намеренно: у переменной, которую экспортирует Claude Code, документированного аналога здесь нет, а угаданное имя молча указало бы не туда. Проверить, что хук вообще находит проект.
4. **Работают ли слэш-команды и не перехватывает ли клиент слово `help`.** Слово справки объявлено без слэша именно на этот случай.
5. **Реальные отказы среды** — как выглядит отказ режима одобрений, чем человек переключает режим, как запросить разрешение. В редакции для Claude это знание добыто боем; здесь раздел `lint.md` «Когда среда не даёт» содержит только общее правило («отказ докладывается, а не подменяется молча») и прямо помечен как ненаполненный. Наблюдали реальный отказ — это находка для вики.

## 3. Чего в этой редакции нет

- **Оценщик готового ответа** (`Stop`-хук `judge.py`). В редакции для Claude отдельная быстрая модель смотрит готовый ответ и возвращает агента, если он не предложил записать найденное знание. Хук вызывает бинарь `claude` с его флагами, выбирает модель внутри подписки Anthropic и разбирает формат логов Claude Code — переносить это подстановкой путей нельзя. Порт потребует: аналога одноразового неинтерактивного вызова, выбора дешёвой модели, защиты от рекурсии и **отдельного разговора о стоимости** — здесь это метрируемые токены на каждом ходу агента. Последствие: страховки за агентом нет, правило «Просьба решена» держится только на его собственной ревизии.
- **Лента миграций** (`migrations/`). В редакции для Claude это упорядоченные структурные обновления для уже собранных проектов. Здесь собранных проектов пока нет, а сами миграции целиком описывают машинерию Claude (`.claude/settings.json`, события, клиент). Заводить ленту имеет смысл с первого структурного обновления **этой** редакции.
- **Автоматическая публикация и привратники CI.** Редакция не публикуется рабочим процессом и не проверяется на полноту changelog и синхронность локалей. Проверка обновлений в `lint.md` переписана на этот репозиторий, но дисциплины версий у редакции пока нет: увидел расхождение версий — скажи человеку, не применяй вслепую.
- **Английская редакция.** Пока только русская.

## 4. Что поменяли по существу, а не переименованием

- Память среды: у ChatGPT есть свои сохранённые воспоминания между чатами, проекту они неподконтрольны. Пункт 5 иерархии источников переписан: память среды — не canonical, всё, что должно пережить чат, идёт в `wiki/`.
- Определение независимой проверки в `review-gate.md` — под субагентов Codex, с явным требованием ставить проверяющему `sandbox_mode = "read-only"`: у Claude запрет на запись — свойство механизма, здесь его надо прописать руками.
- Разделы про удаление и запись хуков в Claude Desktop свёрнуты в один честный раздел `lint.md` «Когда среда не даёт».
- Корневой файл ужат почти вдвое под бюджет инструкций: четыре блока вынесены в `methodology/` и читаются по триггеру — `human-language.md` (четыре вопроса к готовому тексту), `long-run.md`, `extraction.md`, `knowledge-capture.md`. Правила не убраны, изменилось только, что лежит всегда под рукой, а что по требованию.
