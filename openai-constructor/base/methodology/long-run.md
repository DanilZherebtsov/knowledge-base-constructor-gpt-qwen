# Длинный проход — с сохранением прогресса

Читается по триггеру из `AGENTS.md` («В процессе — фаза „действуй“»), когда работа идёт по набору элементов и не укладывается в один сеанс: пачка файлов, обход источников, серия запросов.

**Почему правило есть.** Результат, накопленный только в разговоре, теряется целиком при обрыве чата, сессии или машины — и теряется в момент, который выбираешь не ты.

## Порядок

1. **Пиши на диск по ходу, после каждой пачки, а не в конце.** Обрыв обязан оставить сделанное, а не ноль.
2. **Журнал, логи и промежуточные куски — в `tmp/<операция>-<дата>/`.** Подпапка на прогон.
3. **Первой строкой журнала — задача словами человека.** После сжатия разговора взять их будет неоткуда, а без них продолжение пойдёт по твоему пересказу задачи, а не по ней самой.
4. **Продолжение — по журналу:** что уже обработано, то не переделывается.
5. **Сбойный элемент — в список неудачных, проход движется дальше.** Останавливать весь проход из-за одного элемента нельзя: так теряется и он, и всё остальное.
6. **По завершении и приёмке результата — предложить уборку списком** (что удаляем / что остаётся). Удалять только с подтверждения и не раньше приёмки: до приёмки внутри `tmp/` может лежать единственная копия сделанного.

**Для собственного кода проекта правило строже** — см. механику кода, если она подключена.
