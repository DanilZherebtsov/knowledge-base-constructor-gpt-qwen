# Что проверено, что не проверено, чего нет

Редакция получена переносом с конструктора для Claude Code (16.09.2026). Перенос делался по документации вендора, **боем не проверялся ни разу**. Этот файл существует, чтобы неизвестное было названо, а не выглядело как знание: разбор предыдущей чужой адаптации показал, что ломается конструктор именно там, где адаптирующая модель уверенно предположила, чего у платформы нет.

Цель — `qwen-code` во всех его официальных поверхностях: терминал, десктопное приложение, плагины к редакторам, веб-интерфейс. Они читают один и тот же `QWEN.md` и одну и ту же папку `.qwen/`.

Файл — для человека и для агента при переносе следующих правок. В собранный проект он **не идёт** (см. перечень лесов в `START-HERE.md`, шаг 5).

## 1. Проверено по документации вендора

| Что | Итог |
|---|---|
| Имя корневого файла | `QWEN.md`; загрузка иерархическая — от `~/.qwen/QWEN.md` вниз до корня проекта и ниже по дереву |
| Модульность | контекстные файлы умеют импорт через `@path/to/file.md`; мы им не пользуемся — ссылки обычные, файлы `methodology/` читаются по триггеру |
| Хуки | 20+ событий, в том числе `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PreCompact`/`PostCompact`, `SubagentStart`/`SubagentStop`, `Stop`; конфиг — `.qwen/settings.json` |
| Контракт хука | JSON на stdin; на выход `hookSpecificOutput.additionalContext`, `decision`, `continue`; код выхода `2` блокирует |
| Вброс контекста | `additionalContext` для `UserPromptSubmit` оборачивается в отдельную часть сообщения — то есть остаётся отличимым от текста человека |
| Субагенты | markdown с YAML-фронтматтером в `.qwen/agents/`; поля `name`, `description`, `model`, `approvalMode`, `tools`, `disallowedTools`; именованный субагент стартует с чистого контекста |
| Режим `fork` | наследует историю родителя — **для независимой проверки не годится** (см. `review-gate.md`) |
| Память | инструмент `save_memory` дописывает факт в глобальный `~/.qwen/QWEN.md` под своей секцией — то есть в always-on слой **выше** вики |

## 2. НЕ проверено — смотреть в первую очередь

1. **Исполняются ли хуки** и в каком виде клиент отдаёт `additionalContext` обратно модели. Проза-правила в `QWEN.md` написаны как **пол**: если хук не сработал, проверку делает агент сам. Проверить: запустить сессию в проекте с просроченной профилактикой и посмотреть, приходит ли записка.
2. **Путь запуска хука.** В конфиге команда задана относительным путём (`python3 .qwen/hooks/freshness_check.py`), а сам скрипт ищет корень проекта, поднимаясь от `cwd` до папки с `QWEN.md`. От переменной окружения не зависим намеренно: у переменной, которую экспортирует Claude Code, документированного аналога здесь нет, а угаданное имя молча указало бы не туда.
3. **Точная схема `settings.json`** для хуков — поля `matcher`, `sequential`, `name`, `timeout` описаны, но порядок и обязательность полей мы не проверяли запуском.
4. **Одинаковы ли поверхности.** Терминал, десктоп и плагины заявлены как один агент с общей конфигурацией, но что именно поддерживает десктоп (хуки, субагенты), боем не проверено.
5. **Реальные отказы среды** — как выглядит отказ режима одобрений (`approvalMode`), как человек его переключает. Раздел `lint.md` «Когда среда не даёт» содержит только общее правило («отказ докладывается, а не подменяется молча») и прямо помечен как ненаполненный.
6. **Режимы размышления.** У моделей Qwen есть переключение «думать / не думать». Как оно взаимодействует с длинным always-on файлом и с гейтами — не проверено; правил про это в конструкторе намеренно нет, потому что подтвердить их нечем.

## 3. Чего в этой редакции нет

- **Оценщик готового ответа** (`Stop`-хук `judge.py`). В редакции для Claude отдельная быстрая модель смотрит готовый ответ и возвращает агента, если он не предложил записать найденное знание. Хук вызывает бинарь `claude` с его флагами и разбирает формат логов Claude Code — переносить это подстановкой путей нельзя. Порт потребует аналога одноразового неинтерактивного вызова, выбора дешёвой модели, защиты от рекурсии и **отдельного разговора о стоимости**. Последствие: страховки за агентом нет, правило «Просьба решена» держится только на его собственной ревизии.
- **Лента миграций** (`migrations/`). Заводить имеет смысл с первого структурного обновления **этой** редакции: миграции из редакции для Claude целиком описывают её машинерию.
- **Автоматическая публикация и привратники CI.** Проверка обновлений в `lint.md` переписана на этот репозиторий, но дисциплины версий у редакции пока нет: увидел расхождение версий — скажи человеку, не применяй вслепую.
- **Английская редакция.** Пока только русская.

## 4. Что поменяли по существу, а не переименованием

- **Память.** Пункт 5 иерархии источников переписан под `save_memory`: он пишет в глобальный файл инструкций, который грузится раньше вики и потому её перебивает. Для знания проекта использовать его запрещено — это строже, чем формулировка у Claude, и намеренно.
- **Независимая проверка** в `review-gate.md` — под субагентов Qwen Code, с двумя добавленными правилами: `fork` независимости не даёт (и это отказ, который выглядит как успех), а запрет на запись проверяющему нужно прописывать руками через `tools`/`disallowedTools`.
- **Разделы про удаление и запись хуков в Claude Desktop** свёрнуты в один честный раздел `lint.md` «Когда среда не даёт».
- **Корневой файл ужат почти вдвое:** четыре блока вынесены в `methodology/` и читаются по триггеру — `human-language.md` (четыре вопроса к готовому тексту), `long-run.md`, `extraction.md`, `knowledge-capture.md`. Правила не убраны, изменилось только, что лежит всегда под рукой, а что по требованию. Жёсткого потолка размера у Qwen Code в документации нет, но always-on файл оплачивается в каждом запросе.
